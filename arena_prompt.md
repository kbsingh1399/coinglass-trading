**The Core Problem: Data Provenance & Normalization Gaps**
By analyzing the `featurize()` function alongside the DOM scraping logic, we have identified several critical data discrepancies between what the ML model learned during backtesting and what it sees in live execution.

**Key Divergence Areas:**

1. **Cumulative Volume Delta (CVD) Baseline Resets:**
   - *Backtesting:* `CVD` is a raw, absolute accumulation of tick volume delta over a long historical dataset.
   - *Live:* `data.futures_cvd` is scraped from the Coinglass chart. Coinglass often normalizes CVD based on the user's viewport or daily session resets. If the chart reloads or resets, the baseline shifts. 
   - *Impact:* Features like `cvd_d` (`CVD.diff(5)`) will spike massively (or drop) during a DOM reload or session reset, generating completely artificial ML signals.

2. **Volume and Liquidation Aggregation Windows:**
   - *Backtesting:* `Volume` and `Agg. Liq Long/Short` represent discrete 15-minute candle chunks.
   - *Live:* Coinglass UI elements often display 24H rolling volume or 24H accumulated liquidations depending on the exact widget being scraped.
   - *Impact:* In `featurize()`, we do `df["liql"] = df["Agg. Liq Long"].rolling(5).sum()`. If the live data is scraping a 24H liquidation value, summing it over 5 periods is mathematically invalid and produces garbage data for the ML model compared to the 15m discrete bins in backtesting.

3. **String Parsing & Unit Denominations (Coins vs. USD):**
   - *Backtesting:* Data in Parquet is usually raw numerical values (e.g., base asset volume in BTC, OI in raw USD).
   - *Live:* The DOM scraper parses strings like "1.54M" into `1540000.0`. If Coinglass changes its rounding precision, or if the chart defaults to Base Asset (Coins) instead of Quote Asset (USD) for Open Interest or Volume, the absolute values differ.
   - *Impact:* The `vr5` feature (`df["Volume"] / df["Volume"].rolling(20).mean()`) might survive unit scaling, but absolute threshold inputs into XGBoost will fail completely if the unit base is wrong.

4. **Synchronicity & Data Mixing (WebSocket vs. DOM):**
   - *Live:* `Engine_1.py` pulls `Bid Qty`, `Ask Qty`, and `Delta Qty` (Footprint) accurately via real-time Binance WebSockets, but mixes it in the exact same DataFrame with lagged, DOM-scraped Coinglass metrics (CVD, OI, Liquidations).
   - *Impact:* This temporal desynchronization means footprint deltas do not accurately align with the Coinglass CVD, causing divergence in cross-indicator features.
