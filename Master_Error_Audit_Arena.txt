--- Issue 1.1: Coinglass Indicator 0.0 Overwrite Bug ---
Root Cause: DOM scraper returned 'N/A' when TradingView CSS classes shifted,
which parsed to 0.0 via parse_float(). This overwrote valid values captured
by the HTTP API interceptor (which fires every 500ms with correct data).
Fields affected: rsi, fut_cvd, spot_cvd, liq_long, liq_short, funding,
ls_ratio, oi, coins_bid, coins_ask, dollars_bid, dollars_ask, whale_idx,
tk_buy_cnt, tk_sell_cnt.
Fix Applied: Zero-overwrite guard in SnapshotStore.update() (Engine_1.py
L1046-1060). If incoming value is 0.0 and current stored value is non-zero,
the update is skipped. Protects 15 indicator fields from DOM parse failures.
Commit: 7ed9049

--- Issue 1.2: Binance WebSocket ISP Filtering ---
Root Cause: ISP-level TCP filtering allows the WebSocket handshake to
complete (CONNECTED status) but drops all subsequent data frames. Results
in "WS: CONNECTED | Ticks: 0" in the pipeline status dashboard.
Fix Applied: No code fix possible (ISP-level). REST footprint fallback
(BinanceFootprintFeed polling /fapi/v1/klines every 5s) handles all
pricing data. WebSocket is supplementary only.
Status: Known limitation. REST fallback is the primary price source.

--- Issue 1.3: Binance REST Feed Timeout Too Short ---
Root Cause: aiohttp timeout was 3 seconds, insufficient for Binance
testnet API latency and Windows DNS resolution delays. Caused frequent
"Connection issues detected (all queries failed)" warnings and the
BinanceFootprintFeed entering a degraded state.
Fix Applied: Increased timeout to 8 seconds via
aiohttp.ClientTimeout(total=8) at Engine_1.py L1275.
Commit: eda7f01

--- Issue 1.4: Binance Feed Session Cycling (TCP Connector Rebuild) ---
Root Cause: The aiohttp TCPConnector was rebuilt on every inner loop
iteration when a request failed, causing excessive DNS lookups and
connection establishment overhead. Each failure triggered a full
connector teardown and rebuild.
Fix Applied: Added keepalive_timeout=60 to TCPConnector and 30-minute
session lifetime (time.time() - session_start < 1800) so the TCP
connector persists across transient failures. Session is only refreshed
after 30 minutes of continuous use.
Commit: eda7f01

--- Issue 1.5: Funding Rate Scale Mismatch (UI % vs Decimal) ---
Root Cause: Coinglass UI displays funding rate as percentage (e.g., 0.0100
meaning 0.01%). The JS extraction layer divides by 100 to produce decimal
(0.0001). But the historical parquet stores raw percentage values (~0.06).
If live scraper produces 0.0001 while backtest features were computed on
0.06, the z-score normalizer (zfr) produces incomparable signals.
Fix Applied: Normalization guard in featurize() (six_strategy_engine.py
L196): if abs(v) >= 0.005, divide by 100. Both paths now produce decimal
fractions. Added runtime alert in scraper when raw funding >= 0.5.
Commit: 19bd515

--- Issue 2.1: Buffer Seeding Stuck at 3/250 (Excel Ordinal Timestamps) ---
Root Cause: load_history_from_disk() read Excel timestamps as ordinal date
floats (e.g., 45500.0 = days since 1900-01-01). The filter
"ot < now_open" compared these against Unix epoch seconds (~1.7 billion),
so all candles failed the filter. Buffer received only 3 candles instead
of 250+, preventing any predictions from firing.
Fix Applied: Excel-epoch to Unix-epoch conversion in set_history()
(six_strategy_engine.py L477, L493):
  EXCEL_EPOCH_OFFSET = 25569
  d["open_time"] = int((v - EXCEL_EPOCH_OFFSET) * 86400)
Buffer now loads full 250+ bars instantly from combined_seed_history.xlsx.
Commit: eda7f01

--- Issue 2.2: ATR Floor Guard Missing ---
Root Cause: When candle history was thin (<250 bars) or data quality was
poor, atr_val was near zero. SL = 1.0 * atr_val produced stop distances
of 0.0001, which fell below MIN_STOP_PCT thresholds (0.1%-0.5% of price).
RiskGovernor blocked ALL entries with "Spread risk too high."
Fix Applied: ATR minimum floor at 0.05% of price (six_strategy_engine.py
L585). Ensures minimum viable stop distance even with degenerate ATR.
Commit: eda7f01

--- Issue 2.3: _last_predict_bar Lockout After Seeding ---
Root Cause: set_history() sets _last_predict_bar[symbol] to the last
seeded candle's open_time. The prediction gate checks
"last_bar == _last_predict_bar" and skips if true. Since seeded candles
are historical, the gate remains locked until the first LIVE candle closes
and rolls over (up to 15 minutes). Dashboard shows "Strategies: 0/6 active"
during this period.
Fix Applied: No code change — this is intentional behavior. Prevents
trading on stale seeded history. First prediction fires after first live
15-minute candle rollover. Documented as expected behavior.
Status: Working as designed.

Fix Applied: Non-modeled symbol guard (six_strategy_engine.py L592-595):

--- Issue 2.7: Division-by-Zero in _zscore During Zero-Variance Periods ---
Root Cause: _zscore() computes (series - mean) / std. During flat price
periods, std = 0, producing NaN/Inf features that corrupt ML predictions.
Resolution: _zscore uses .replace(0, 1e-10) on std (L87). featurize()
applies .fillna(0).replace([np.inf, -np.inf], 0) as final sweep (L224).
12 zero-guards and 14 fillna(0) calls across featurize().
Status: Verified sound. No NaN/Inf can reach the ML model.

--- Issue 3.1: sl_dist NameError in check_exits() ---
Root Cause: Line 806 referenced bare variable sl_dist in the trailing
stop fallback: "trail_dist = 0.8 * entry_atr if entry_atr > 0 else
(0.8 * sl_dist if sl_dist else 0.0)". But sl_dist was never assigned in
the check_exits() scope — it was only stored in the trade dict as
trade['sl_dist']. When entry_atr == 0, Python evaluates the else branch
and raises NameError: name 'sl_dist' is not defined.
Fix Applied: Changed to read from trade dict:
  sl_dist_val = trade.get('sl_dist', abs(entry_price - sl))
  trail_dist = 0.8 * entry_atr if entry_atr > 0 else
               (0.8 * sl_dist_val if sl_dist_val > 0 else 0.0)
Commit: a0c33d7

--- Issue 3.2: Hard TP Exit Kills Trailing Stop (OOS Divergence) ---
Root Cause: check_exits() had a hard TP exit: "current_price >= tp ->
should_close = True, reason = 'TP'". The OOS backtest (_sim_trade in
six_strategy_engine.py) has NO hard TP exit — it uses ONLY the trailing
stop ratchet after 5R profit, allowing trades to capture 6R-8R+ gains.
The live engine closed at exactly 5R, leaving 20-60% of potential
profits on the table. This was the single largest OOS divergence.
Fix Applied: Removed hard TP exit from check_exits(). Exit now occurs
ONLY via: (1) SL hit (including trailing SL), or (2) MAX_BARS timeout.
Matches OOS _sim_trade behavior exactly.
Commit: a0c33d7

--- Issue 3.3: Timeout Duration 3x Too Short ---
Root Cause: check_exits() used elapsed_time >= 86400 (24 hours = 96 bars)
as the MAX_BARS timeout. The OOS backtest uses MAX_BARS = 288 (288 bars x
15 min = 72 hours = 259,200 seconds). Live engine force-closed profitable
trending trades after 24 hours instead of letting them run for 72 hours.
Fix Applied: Changed timeout from 86400 to 259200 seconds
(288 x 15 x 60). Matches OOS MAX_BARS exactly.
Commit: a0c33d7

--- Issue 3.4: BinanceToMT5Adapter Class Placement Bug ---

Commit: e726f77

--- Issue 3.5: NAKED GUARD — SL Placement Failure Recovery ---
Root Cause: If entry order fills on Binance but the corresponding
STOP_MARKET algo order fails (network error, API rejection), the position

Fix Applied: NAKED GUARD in BinanceBroker.execute_trade() (L209-211):

--- Issue 3.6: Tight SL Sizing Bug ($769 Loss on $20 Risk) ---
Root Cause: Position sizing formula: units = risk_capital / stop_dist.
For TRXUSDT: stop_dist = 0.0011 (0.03% of price), risk_capital = $20.
units = 18,181 contracts. Bid-ask spread (~0.001) matched the stop
distance, so the position was stopped out instantly on open.
Actual loss: -$769.02 (38x intended risk).
Fix Applied: Per-symbol MIN_STOP_PCT floor in trigger_entry()
(Engine_1.py L589-604). BTC: 0.1%, TRX/DOGE: 0.4%, default: 0.3%.
Entries where stop_dist < min_stop_dist are rejected before sizing.
Also added MAX_NOTIONAL = $50,000 cap.
Commit: d88a12b

--- Issue 4.1: Capital Baseline Override by Stale Trade Log ---
Root Cause: Engine_1_trade_logs.json had "daily_start_capital": 0.0 from
a reset. In load_history(), meta.get('daily_start_capital', self.current_capital)
returned 0.0 (not missing — explicitly zero), overriding the correct live
Binance balance ($4,951.32) set in __init__. daily_start_capital = 0.0
disabled the daily DD guardrail (division by zero guard returned 0.0).
Fix Applied: Changed load_history() to treat daily_start_capital <= 0
as "not set" and fall back to self.current_capital:
  meta_daily_start = meta.get('daily_start_capital', 0.0)
  self.daily_start_capital = (meta_daily_start if meta_daily_start > 0
                              else self.current_capital)
Also cleaned trade log to omit daily_start_capital on reset.
Commit: d1182ca

--- Issue 4.2: Emergency Halt from Stale Trade Log on Startup ---

current_capital. Risk Governor calculated daily_dd = 7.09% on startup,
exceeding the 4.5% threshold. EMERGENCY_HALT triggered immediately,
blocking ALL trading before a single signal was evaluated.
Fix Applied: New session detection in load_history(): if
last_rollover_day != today, reset daily_start_capital = current_capital.
Prevents stale cumulative losses from triggering intraday halt.
Commit: d88a12b

--- Issue 4.3: Daily DD Reset on New Session ---
Root Cause: Same as 4.2. The daily drawdown counter persisted across

(Europe/Athens timezone).

--- Issue 5.1: NTFS Permission Errors on .git/objects ---
Root Cause: Windows NTFS file permissions prevented git fetch from
unpacking new commit objects into the local object store. Local repo

--- Issue 5.2: Terminal Freeze from Rich Live + stdout Conflict ---
Root Cause: render_table() constructed Rich UI layout tables synchronously
inside the asyncio event loop every 0.5 seconds. Building 18-symbol x
20-column Rich tables took 0.5-1.2s of CPU time per frame, blocking the
event loop. Additionally, calling stdout print() while Rich Live was
active corrupted Rich's screen cursor control, causing terminal freeze.
Fix Applied: (1) Offloaded render_table to asyncio.to_thread() so CPU-bound
Rich layout creation runs in ThreadPoolExecutor, not the event loop.
(2) Eliminated all stdout print() during active Rich Live rendering.
(3) Raised event_loop_monitor threshold from 0.5s to 2.0s and silenced
its output entirely.
Commit: b6fc698

--- Issue 5.3: Event Loop Blocking from Synchronous Calls ---
Root Cause: pd.read_parquet(), openpyxl operations, and json.load() ran
synchronously inside the async event loop during seeding and startup.
Fix Applied: These operations run during seeding phase (before real-time
feeds start) or in background threads (retraining loop uses time.sleep
in a daemon thread, not the async loop). ML predictions offloaded via
asyncio.to_thread(). Broker calls offloaded via broker_executor
(ThreadPoolExecutor). No blocking calls remain in the hot path.
Status: Verified sound.

--- Issue 5.4: Trade History Unbounded Growth ---
Root Cause: self.history list grew with every closed trade without any
trimming. Over months of continuous operation, the list and its JSON
serialization would grow unbounded, slowing save_history() and load_history().
Fix Applied: Added trim in save_history():
  if len(self.history) > 5000:
      self.history = self.history[-5000:]
Caps history at 5000 most recent trades (~800KB JSON).
Commit: 8f44de5

--- Issue 5.5: Premature Return on Missing COINGLASS Credentials ---
Root Cause: Startup code had an early return when COINGLASS_EMAIL or
COINGLASS_PASSWORD environment variables were not set, preventing the
engine from continuing to the live trading phase even when using
persistent browser profiles (already logged in).
Fix Applied: Removed premature return. Engine continues startup flow
regardless of credential env vars, relying on persistent browser session
cache for authentication.
